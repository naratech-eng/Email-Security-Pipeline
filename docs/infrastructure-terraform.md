# Infrastructure (Terraform)

All AWS infrastructure is managed by Terraform. This page describes the layout, state strategy, and the order things are created in.

## 1. Repository Layout

```
infra/
├── bootstrap/                  # one-time: S3 + DynamoDB for remote state
│   └── main.tf
├── envs/
│   ├── dev/
│   │   ├── backend.tf
│   │   ├── main.tf
│   │   ├── variables.tf
│   │   └── terraform.tfvars
│   └── prod/
│       └── ...                 # mirrors dev
└── modules/
    ├── network/                # VPC, subnets, NAT, security groups
    ├── ecr/                    # container registry
    ├── ecs_service/            # Fargate service + ALB target group
    ├── alb/                    # public + internal ALBs
    ├── rds_postgres/           # RDS instance + subnet group
    ├── s3_bucket/              # reusable bucket with secure defaults
    ├── ec2_mailserver/         # Rocky Linux 9 + cloud-init for Postfix/Dovecot
    ├── cognito/                # user pool + app client
    ├── waf/                    # WAF web ACL + association
    └── observability/          # CloudWatch log groups, alarms, dashboards
```

## 2. State Backend

- **S3 bucket** for state, **DynamoDB table** for locking
- Both created by the `infra/bootstrap` module on day one
- State is encrypted with KMS, versioning enabled, public access blocked

```hcl
# infra/envs/dev/backend.tf
terraform {
  backend "s3" {
    bucket         = "esp-tfstate-<account-id>"
    key            = "envs/dev/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "esp-tflock"
    encrypt        = true
  }
}
```

## 3. Provisioning Order

1. **Bootstrap** state backend (`infra/bootstrap`) — once per account
2. **Network** module → VPC, subnets, NAT, default SGs
3. **S3** buckets → datasets, models, logs
4. **ECR** repository → backend image
5. **RDS Postgres**
6. **ALBs** (public + internal) and **WAF**
7. **ECS service** for FastAPI (initial image can be a placeholder until M6)
8. **Cognito** user pool + app client
9. **EC2 mail server** with cloud-init that installs Postfix + Dovecot
10. **Amplify app** (or do this in the AWS console pointed at the GitHub repo, then import to TF)
11. **Observability** module → log groups, alarms, dashboards

## 5. Workflows

- **PR:** `terraform fmt -check`, `terraform validate`, `tfsec`, `checkov`, `terraform plan` against dev workspace, post plan as PR comment.
- **Merge to main:** `terraform apply` against dev. Requires green PR.
- **Release tag:** `terraform apply` against prod with manual approval.

## 6. Secrets

Defined as inputs to modules, **never hard-coded**:
- DB master password generated by `random_password`, stored in Secrets Manager
- App secrets created by Terraform but values rotated via Secrets Manager rotation
- Cognito user pool client secret retrieved at runtime from SSM Parameter Store

## 7. Cost Controls

- Budget alarms at 50% / 80% / 100% of monthly target
- Single NAT gateway in dev; consider VPC endpoints for AWS APIs to reduce NAT data charges
- ECS service `desired_count = 1` outside demo windows
- RDS: single-AZ, smallest class, automated stop schedule via `aws_lambda_function` (optional)
- S3 lifecycle to transition old datasets to S3 Glacier

## 8. Rollback / Destroy

- `terraform destroy -target=module.ecs_service` to remove just the API
- Full teardown: `terraform destroy` (state bucket and DynamoDB stay; bootstrap is destroyed separately)
- RDS: snapshot before destroy if data must be kept

## 9. Out of Scope (for now)

- Multi-account (Control Tower)
- Multi-region failover
- Service Catalog / Landing Zone
