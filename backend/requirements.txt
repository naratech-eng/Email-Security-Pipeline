# Pinned to exact versions (SonarCloud S8544 / docs/devsecops.md §3.5 --
# "Python dependencies unpinned" was a named gap; this closes it). Pins are
# the newest-compatible resolution as of 2026-08-05 via `pip-compile` against
# the previous >= floors -- deliberately NOT rolled back to those floors:
# numpy>=1.26 has no wheels for Python 3.13 (this project's runtime), so the
# unpinned installs were already silently resolving to a modern release on
# every fresh build. Pinning today's resolution doesn't add new version risk
# over what was already running; it stops FUTURE silent drift and makes
# builds reproducible. Dependabot (.github/dependabot.yml) now owns keeping
# these current instead of floating `>=` ranges doing it implicitly.
#
# Scoped to DIRECT dependencies only, not a full pip-compile transitive lock
# (~75 packages) -- simpler to maintain, and Dependabot's pip ecosystem
# operates cleanly on direct pins without fighting a resolver-locked file.
#
# ⚠️ This changes what pandas/scikit-learn/tensorflow actually load, which
# matters because the M6 models were joblib/TF-serialized against whatever
# versions were installed at training time, possibly much older than these.
# backend-tests.yml's integration tests load the REAL S3 models -- do not
# merge a PR touching this file until that workflow is green.
